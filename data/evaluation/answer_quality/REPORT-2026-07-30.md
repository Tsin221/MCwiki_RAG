## 主要失败与原因

### 1. Java 版 1.21 召回失败

`java-1-21-content` 的期望页面没有进入最终 8 条证据，回答因此明确拒答。这一行为
符合证据边界，但没有完成用户问题。

进一步检查显示：

- BM25 路径没有返回候选；
- 语义结果被“大事记”、1.21.1、1.21.2、1.21.3 等相似版本占据；
- 期望的 `/1.21` 页面和内容更完整的 `/Java版1.21` 页面均未进入双路 Top-20
  候选。

因此，Reranker 当前无法修复此问题：Reranker 只能重排候选，不能重排一个根本没有
被召回的页面。优先方向应是版本号查询规范化、查询词拆分、标题精确加权或版本页面
别名处理。

### 2. 灾厄巡逻队光照条件写反

`illager-patrol` 回答称 Java 版生成位置的方块光照“需大于 8”，而引用证据明确写
的是“不大于 8”。这是一次模型对证据的反向解读，引用编号本身有效，但引用并不支持
对应表述。

这说明“引用编号有效率 100%”不能替代语义层的引用复核。该题应加入后续提示词或
回答验证的固定回归集。

### 3. 苦力怕掉落回答不完整

`creeper-behavior` 正确回答了火药掉落，但没有覆盖特定击杀条件下的音乐唱片和生物
头颅。问题包含“哪些物品”，后续可通过问题子任务覆盖检查或提示词强调多问句完整性。

## Reranker 决策

本轮结论：**暂不接入 Reranker。**

理由：

1. 当前整体指标已经达到建议门槛；
2. 唯一的期望来源召回失败不在双路 Top-20 候选中，Reranker 无候选可排；
3. 另两个主要问题分别属于回答忠实度和完整性，不是排序问题；
4. 先做针对性修复可以用更低复杂度获得更明确收益。

在完成版本查询召回修复后，应使用同一数据集重新生成基线。如果届时候选已经进入
Top-20、但仍无法进入最终证据，再评估 Reranker 才有依据。

## 建议后续顺序

1. 修复版本号问题的 BM25/标题召回，并确保 Java 版 1.21 进入候选；
2. 将灾厄巡逻队光照条件作为回答忠实度回归案例；
3. 改进多子问题和“哪些”类问题的完整性约束；
4. 使用同一 18 题重新跑基线，对比本报告；
5. 指标有明确排序瓶颈后再评估 Reranker。
