# Three.js 问答前端设计

状态：已确认，待实施

更新时间：2026-07-29

## 1. 决策

问答 Web MVP 使用 Three.js 提供 Minecraft 风格的沉浸式动态背景。在 React
项目中通过 `@react-three/fiber` 管理 Three.js 场景，并按需使用
`@react-three/drei` 的轻量辅助能力。

Three.js 只负责装饰性三维场景。问题输入、流式回答、引用编号、来源卡片、错误提示
和所有可交互控件继续使用普通 React DOM 渲染。

```text
浏览器页面
├─ Three.js Canvas：氛围、方块地形、粒子和状态动效
└─ React DOM：问答、引用、来源、输入框和错误状态
```

选择这种分层方式是为了同时获得视觉表现、文字可读性、无障碍能力和稳定的移动端
交互。第一版不使用 WebGL 绘制聊天文字，也不让用户必须操作三维场景才能提问。

## 2. 设计目标

- 第一眼具有明确的 Minecraft 世界观和辨识度；
- 在深色沉浸式背景上保持回答与引用清晰可读；
- 三维场景可以轻微响应“检索、生成、完成和失败”等问答状态；
- 页面先保证问答可用，再逐步加载视觉效果；
- 桌面端提供完整效果，移动端和低性能设备能够平稳降级；
- 不照搬参考网站的品牌、模型或素材，只借鉴空间感、光影和构图方式。

## 3. 第一版视觉方向

### 3.1 主题

采用“深海夜空中的浮空方块岛”方向：

- 背景：深蓝黑渐变与轻雾；
- 主体：页面右侧或右下方的低多边形浮空方块岛；
- 点缀：少量青绿色粒子、星点和柔和光晕；
- 强调色：信标青、经验绿和低饱和冰蓝；
- 内容区：半透明深色面板，保持足够对比度；
- 动画：缓慢漂浮、非常轻的镜头视差和状态呼吸光。

建议的基础色：

| 用途 | 色值 |
|---|---|
| 页面底色 | `#07111F` |
| 深层背景 | `#020711` |
| 主强调色 | `#22D3C5` |
| 次强调色 | `#60A5FA` |
| 成功状态 | `#6EE7A8` |
| 正文 | `#F4F7FB` |
| 次级文字 | `#A8B3C2` |
| 内容面板 | `rgba(7, 17, 31, 0.82)` |

最终实现前应在真实页面中验证颜色对比度，正文和交互文字至少满足 WCAG AA。

### 3.2 页面构图

桌面端：

- 问答内容位于左侧至中部，阅读区域最大宽度约 840px；
- 三维主体偏右，不遮挡聊天内容和输入框；
- 来源卡片使用稳定的二维布局；
- 输入区始终处于最高交互层级。

移动端：

- 问答区域占据主要视口；
- 三维主体移至背景下半部，降低透明度、面数和粒子数量；
- 必要时仅保留渐变、雾气和少量方块轮廓；
- 360px 宽度下不得产生横向滚动。

## 4. 三维场景范围

第一版场景只包含：

- 一个由简单方块或低多边形几何体组成的浮空岛；
- 环境光、主方向光和有限的轮廓光；
- 少量可复用粒子；
- 轻雾和背景渐变；
- 非强制的指针视差；
- 与问答状态关联的颜色或亮度变化。

第一版优先使用程序化几何体和自有材质，不依赖来源不明的外部模型或纹理。若后续
引入第三方资产，必须记录来源、许可和压缩后的体积。

明确不做：

- 三维聊天气泡或三维文字；
- 第一人称漫游、复杂相机控制或三维导航；
- 物理模拟；
- 大型 GLTF 场景；
- 重型后处理链和高成本自定义 Shader；
- 依赖三维交互才能完成的产品功能；
- 对参考图进行像素级复刻。

## 5. 状态动效

三维效果是辅助反馈，不能成为唯一的状态提示。DOM 中始终保留明确文字。

| 问答状态 | DOM 提示 | 可选三维反馈 |
|---|---|---|
| 空闲 | 示例问题和输入提示 | 缓慢漂浮、低亮度粒子 |
| 检索中 | “正在检索 Wiki” | 粒子轻微向主体聚拢 |
| 生成中 | 流式显示回答 | 核心区域缓慢增强青色光 |
| 完成 | 回答和来源完整显示 | 一次短促柔和的光晕 |
| 证据不足 | 明确说明资料不足 | 降低主体亮度 |
| 错误或中断 | 错误说明与重试按钮 | 停止状态动画，不闪烁 |

状态切换应平滑，单次强调动画建议控制在 150～400ms。持续动画必须低速、低振幅，
不得干扰阅读。

## 6. 可用性与无障碍

- Canvas 使用 `pointer-events: none`，不截获输入框、链接和按钮操作；
- 所有核心功能只通过键盘和 DOM 即可完成；
- 焦点样式清晰可见；
- 不使用仅靠颜色表达的状态；
- 三维 Canvas 对辅助技术隐藏，并提供有意义的页面标题和文字说明；
- 遵循 `prefers-reduced-motion`，关闭视差、旋转和非必要持续动画；
- 正文与背景对比度至少达到 4.5:1；
- 来源链接具有可辨识的悬停和键盘焦点状态；
- 流式文本更新不能反复抢占焦点或强制滚动用户正在阅读的位置。

## 7. 性能与降级

### 7.1 加载策略

- React 问答 UI 先渲染，三维场景延迟加载；
- Three.js 相关代码使用独立异步分包；
- 场景加载失败不能影响提问、流式回答或来源链接；
- 首屏不下载大型三维模型和未压缩纹理。

### 7.2 质量等级

桌面高质量：

- 设备像素比上限建议为 1.5；
- 保留完整浮空岛、雾和粒子；
- 目标为稳定 60 FPS。

移动或低性能质量：

- 设备像素比上限建议为 1；
- 降低粒子数量、阴影质量和几何复杂度；
- 关闭指针视差和非必要后处理；
- 目标为稳定 30 FPS 以上。

静态降级：

- 不支持 WebGL、场景初始化失败或用户要求减少动态效果时，显示 CSS 渐变和静态
  方块轮廓；
- 降级后页面布局和所有问答功能保持不变。

### 7.3 生命周期

- 页面隐藏时暂停渲染或降低帧率；
- 组件卸载时释放几何体、材质、纹理和监听器；
- 不为每个粒子创建独立 React 组件；
- 避免在每一帧触发 React 状态更新。

## 8. 验收标准

完成以下条件后，Three.js 前端增强可以标记为完成：

1. Three.js Canvas 与 React 问答层明确分离；
2. 三维场景加载失败时仍可完成完整问答流程；
3. 检索、生成、完成和错误状态均有明确 DOM 提示；
4. 桌面端三维主体不遮挡回答、来源和输入框；
5. 360px 移动端无横向滚动且问答功能完整；
6. `prefers-reduced-motion` 下关闭非必要动画；
7. 键盘可以完成输入、发送、重试和打开来源；
8. 页面隐藏和组件卸载时正确停止或释放三维资源；
9. 生产构建成功，真实浏览器控制台无错误；
10. 桌面端保持流畅，移动端降级模式保持 30 FPS 以上；
11. Three.js 不改变 `/answers`、SSE 或匿名 Cookie 的接口契约；
12. 所有第三方视觉资产均有明确许可记录。
