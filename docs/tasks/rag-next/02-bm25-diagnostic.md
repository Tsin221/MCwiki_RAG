# 任务 02：BM25 专项诊断与对照实验

## 任务目标

解释当前 BM25 Hit@20 仅为 1/15 的原因，并用精确词法查询专项题集比较若干查询策略。
本任务首先产出诊断证据，不直接替换生产默认策略。

建议分支：`codex/bm25-diagnostic`

## 背景

当前 BM25 使用 SQLite FTS5 trigram，并把大部分自然语言问题作为完整短语查询。现有 15 题
偏向自然语言改写，语义检索承担了主要召回。低 Hit@20 可能来自题集类型，也可能来自完整
短语匹配策略，不能直接解释为 BM25 无价值。

## 范围

1. 新建 30～40 个词法专项查询；
2. 实现可插拔的实验查询策略；
3. 对比当前策略、关键短语/实体策略、OR 词项策略和标题优先策略；
4. 记录 Hit@K、MRR@K、空结果率、延迟和逐题排名；
5. 给出是否改生产默认策略的证据结论。

## 专项题型

- 中文实体名称和英文别名；
- Java版、基岩版及精确版本号；
- 快照、预发布版和发布候选编号；
- 命令、命名空间 ID 和 NBT 字段；
- 精确数值、距离、高度、持续时间；
- 包含无关修饰语的长问题。

## 实验约束

- 所有策略使用同一 BM25 数据库、同一题集和同一 K；
- 每次结果都保留 chunk ID、source、title 和排名；
- 不把 BM25 原始分数与向量分数直接相加；
- 不引入新的中文分词依赖，除非先证明 trigram 无法满足需求并单独记录依赖代价；
- 生产 `search_bm25` 默认行为只有在对照结果明确更优且旧 18 题不退化时才能调整。

## 建议实现

在诊断模块中定义具名策略，例如：

- `literal_phrase`：当前行为；
- `entity_phrase`：抽取版本号、命令、标题候选和实体短语；
- `token_or`：受控 OR 查询，必须正确转义 FTS 语法；
- `title_boost`：标题优先但不强制完整标题相等。

诊断工具必须允许显式选择策略，不得通过隐藏环境状态改变实验。

## 建议文件边界

主要修改或新增：

- `data/evaluation/lexical_questions.json`；
- `code/rag_bm25_diagnostics.py`；
- `code/rag_retrieval/bm25_query.py`（如需提取纯函数）；
- 对应测试和实验报告。

除非验收数据支持，不修改 `rag_retrieval/bm25.py` 的默认搜索结果。

## 验收标准

- [ ] 30～40 个问题覆盖全部专项题型；
- [ ] 至少比较三种策略，包含当前策略；
- [ ] 每种策略输出 Hit@5、Hit@10、Hit@20、MRR@10、空结果率和 P50/P95 延迟；
- [ ] 报告包含逐题排名，不能只给均值；
- [ ] 查询转义有单元测试，恶意或异常 FTS 字符不会破坏 SQL；
- [ ] 若建议切换默认策略，旧 18 题最终证据召回不得下降；
- [ ] 不调用 DeepSeek，不修改历史基线。

## 验证

运行后端完整测试，并运行所有策略的同数据集对照。报告应明确指出“题集收益”与“生产收益”
的区别。

## 交接重点

交付一个明确结论：保持现状、替换查询构造，或保留为仅针对精确实体查询的补充路径。
如果结果混合，不得为了提高总体均值合并或删除失败题。
