# 任务 05：章节感知与父子块原型（条件任务）

## 启动条件

只有任务 01～04 的失败分析证明以下至少一项成立时才执行：

- 必要事实经常被 800 字符窗口拆散；
- 相关子块命中，但回答需要同一小节更大的上下文；
- 历史、导航、数据表等章节长期挤占最终证据；
- 多子问题补检仍无法取得完整条件。

若没有这些证据，本任务应标记为“不启动”，不得仅因父子块是高级技术就重建索引。

建议分支：`codex/section-chunking-prototype`

依赖：任务 01～04 的失败报告。

## 任务目标

在隔离的实验产物中验证章节感知分块和“子块检索、父块回答”是否优于当前 800/120 字符窗口。

## 范围

1. 研究原始 Wiki 文本中可稳定识别的章节边界；
2. 设计 parent、section、child 的稳定 ID 与元数据；
3. 仅对一个代表性子集建实验索引；
4. 与当前分块做同题 A/B；
5. 给出是否值得全量重建的成本评估。

## 数据契约要求

每个 child 至少保留：

- `chunk_id`、`parent_id`、`document_id`；
- 页面标题、章节路径、来源 URL；
- 子块序号和原文字符范围；
- 数据版本或生成指纹。

回取 parent 时不得默认使用整篇页面。父块应以可控制的小节或相邻窗口为单位，并受上下文预算
限制。

## 实验要求

- 选择至少 100 个页面，包含长页面、短页面、历史章节和数据表；
- 使用 v2 中所有跨块与多子问题案例；
- 比较块数量、索引体积、Recall@K、Context Precision、要点覆盖和延迟；
- 抽样检查章节标题、表格、数字、否定词和版本信息是否保真；
- 实验索引使用新名称，不能覆盖 `mcwiki_chunks` 和现有 BM25 数据库。

## 建议文件边界

- 新增原型模块和测试；
- 输出到明确标记为实验的目录；
- 新建 Qdrant collection 名称，例如带 `experiment` 和配置指纹；
- 不修改生产默认启动配置。

## 验收标准

- [ ] 能从 child 可靠回到父小节及原始来源；
- [ ] 所有 ID 稳定且无冲突；
- [ ] 跨块问题 Recall 或要点覆盖有可复现提升；
- [ ] Context Precision 没有明显下降；
- [ ] 报告包含全量重建预计时间、磁盘和回滚方案；
- [ ] 若收益不足，明确建议停止，不把原型切换为生产默认。

## 安全与清理

实验 collection 和文件必须与生产数据隔离。删除实验数据属于单独操作，交接时只提供清理命令，
不要在没有授权时删除现有索引或数据卷。
