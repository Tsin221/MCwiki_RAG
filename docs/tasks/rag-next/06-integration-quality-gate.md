# 任务 06：集成回归、人工复核与后续决策

## 任务目标

将已通过单项验收的改动整合到一个候选版本，运行统一离线与真实回答回归，判断哪些改动应进入
生产默认，并决定是否有证据启动 Reranker、GraphRAG 或 Agentic RAG。

建议分支：`codex/rag-next-integration`

依赖：任务 01～04 已完成；任务 05 仅在满足启动条件时纳入。

## 集成原则

- 逐个合并任务，每合并一个就运行测试；
- 不在集成分支重新实现各任务；
- 冲突必须依据公共数据契约解决；
- 某项实验未达到自己的验收门槛时，不切换生产默认；
- 所有新结果使用新文件名，保留 7 月和 9 月历史基线。

## 必须运行的评测

1. 原固定 18 题完整链路；
2. v2 可回答与无答案题；
3. BM25 专项题集；
4. 多子问题子集；
5. 如执行任务 05，再运行跨块子集。

## 必须报告的指标

- Recall@5/10/20、Precision@K、HitRate、MRR；
- preferred source 与 acceptable source 的召回/引用分别统计；
- 答案要点覆盖率、正确性、忠实度、切题程度；
- 引用有效率和引用对声明的支持率；
- 无答案拒答率和误答率；
- P50/P95 检索、生成和总延迟；
- 每题模型调用次数、补检次数；
- 若可取得，记录估算 Token 与调用成本。

## 人工复核

至少抽查：

- 全部失败题；
- 所有阈值附近题；
- 10 个随机通过题；
- 所有无答案题；
- 所有发生补充检索的题。

LLM 评分必须标为辅助评分，不能写成独立人工复核。人工复核记录应包含审阅人、时间、结论和
简短理由。

## 高级技术启动门槛

### Reranker

只有在正确候选稳定进入 Top-20、但进入最终证据 Top-8 的比例不足，且问题集中在排序时启动。

### GraphRAG

只有 v2 出现稳定的跨页面实体关系、多跳路径失败，并且普通多查询无法解决时启动。

### Agentic RAG

只有固定单次/多查询管道无法预先确定检索步骤，且有限补检能显著提高质量时启动。必须同时设置
调用次数、时间、费用和停止原因。

### 不启动

如果失败主要来自标签错误、分块损失、答案遗漏或知识库缺失，应修对应层，不能用高级架构掩盖。

## 验收标准

- [ ] 后端完整测试、前端测试、类型检查和构建通过；
- [ ] 原 18 题无关键指标退化；
- [ ] v2 各类别均单独报告，不以总平均掩盖失败；
- [ ] 多子问题完整性达到任务 04 门槛；
- [ ] 无答案误答率不高于当前基线；
- [ ] 性能与调用成本在约定预算内；
- [ ] 产出一份明确的合并/回退清单；
- [ ] 更新 `PROJECT_STATUS.md`、`MVP_PLAN.md` 和交接文档中的最新口径。

## 最终交付

- 集成分支及提交哈希；
- 新基线原始输出、人工复核、汇总 JSON 和 Markdown 报告；
- 每项实验的启用或回退决定；
- 下一阶段只保留有失败证据支持的任务，不给出泛化的“继续优化”清单。
