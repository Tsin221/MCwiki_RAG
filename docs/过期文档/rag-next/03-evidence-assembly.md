# 任务 03：证据组织与上下文纯度改进

## 任务目标

在不改变检索候选生成方式的前提下，减少最终上下文中的重复块、同页面历史噪声和来源挤占，
同时保住多子问题所需证据。

建议分支：`codex/evidence-assembly`

依赖：任务 01 已合并。

## 背景

当前 `build_evidence` 只按完整文本去重和字符预算截断。苦力怕问题的 8 条证据中，多条来自
同一页面，包含历史记录和重复主题。正确证据已召回，但上下文组织未显式考虑来源多样性、
相邻块关系和问题要点。

## 范围

1. 建立证据选择的离线对照工具；
2. 比较当前策略与来源级去重/限额、相邻块合并、冗余抑制；
3. 保留证据到原始 chunk ID 的映射；
4. 只有 v2 评测证明改进时才切换生产默认策略。

## 必须比较的策略

- 当前 ranked-first 策略；
- 单来源最大块数限制；
- 同一文档相邻 chunk 合并；
- 基于规范化文本重叠的轻量冗余抑制。

MMR 可以作为实验项，但不得直接加入大型模型依赖。若使用 MMR，必须说明相似度来源及中文
文本适用性。

## 设计约束

- Evidence ID 必须稳定、连续，引用仍能回到实际展示的证据；
- 合并证据必须记录所有组成 chunk ID，不能伪造新的来源；
- 不得仅按 URL 去重后丢掉同页面不同小节的互补事实；
- 字符预算仍必须严格执行；
- 空证据和单条超长证据行为应有明确测试；
- 默认最多每个来源占几条必须由评测校准，不能凭感觉固定。

## 建议文件边界

- 新增 `code/rag_evidence.py`，把证据选择从模型客户端中分离；
- 修改 `code/rag_answer.py` 以调用公共选择器；
- 新增 `code/tests/test_evidence.py`；
- 新增本任务的离线对照结果与报告；
- 如需配置，集中到 `rag_settings.py`。

不要修改 BM25、Qdrant 查询或多子问题流程。

## 验收标准

- [ ] 所有策略可在同一候选输入上复现；
- [ ] v2 的相关证据 Recall 不低于当前策略；
- [ ] Context Precision 或人工相关性比例提高，且给出逐题证据；
- [ ] 多证据题不会因来源限额丢失必要小节；
- [ ] 引用编号有效率保持 100%；
- [ ] 旧 18 题的期望来源进入证据保持 15/15；
- [ ] 后端完整测试通过。

## 验证

先使用已保存的检索结果进行离线比较。只有离线验收通过后，才运行真实 18 题完整链路。
不得在策略尚未确定时消耗模型调用做盲目试验。

## 回退要求

若新策略只减少块数但降低答案要点覆盖，应保留诊断工具，生产默认继续使用旧策略，并在报告中
说明失败原因。
